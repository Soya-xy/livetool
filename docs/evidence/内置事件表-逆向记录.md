# 内置事件表（rule / handlerRule）逆向记录

来源：《AKA直播》新版 2026-09-24 版（`abi\AKA直播.exe`，SHA-256 `84FE65D7…`）
方法：主程序加壳，但**代码段在进程内存里是解密的**。从 `analysis\working\chain-runtime\main-dump.bin`
（90,042,368 字节运行内存映像）直接读出字符串常量与比较指令。

**结论：内置事件表不需要脱壳也能读出来。** 事件 ID 与中文名对照在前端 i18n 里是明文，
Go 侧的分派 switch 字符串常量内联在机器码里，两者都能直接读到。

---

## 1. 事件 ID 与中文名

前端 i18n（`_ab_assets_index.6ddd940d.js`，`index.builtInEvent` 一族）与 Go 侧完全一致：

| # | 事件 ID | 中文名 | 需要持续时间 | 额外字段 |
|---|---|---|---|---|
| 1 | `kill_process_name` | 结束指定进程名 | 否 | 进程名（占位 `app.exe`） |
| 2 | `run_exe` | 运行一个应用程序 | 否 | 应用程序路径 |
| 3 | `shutdown` | 关机 | 否 | — |
| 4 | `restart` | 重启 | 否 | — |
| 5 | `sleep` | 睡眠 | 否 | — |
| 6 | `viewlock` | 锁屏 | 否 | — |
| 7 | `logoff` | 注销 | 否 | — |
| 8 | `minimized` | 最小化当前窗口 | 否 | — |
| 9 | `lock_awsd` | 锁定AWSD(罚站) | 是 | — |
| 10 | `lock_wsd` | 锁定WSD，自动按A(自动向左) | 是 | — |
| 11 | `lock_asd` | 锁定ASD，自动按W(自动向前) | 是 | — |
| 12 | `lock_awd` | 锁定WAD，自动按S(自动向后) | 是 | — |
| 13 | `lock_aws` | 锁定WAS，自动按D(自动向右) | 是 | — |
| 14 | `cf_quit_room` | 退出房间(穿越火线) | 否 | — |

前端模板里「持续时间(ms)」的显示条件（排除 9 项后，只剩 5 个锁定事件）：

```
n.rule_event !== "kill_process_name" && n.rule_event !== "run_exe"
  && n.rule_event !== "shutdown" && n.rule_event !== "restart"
  && n.rule_event !== "sleep" && n.rule_event !== "viewlock"
  && n.rule_event !== "logoff" && n.rule_event !== "minimized"
  && n.rule_event !== "cf_quit_room"
```

相关 i18n 键：`builtInEvent` 内置事件 · `selectBuiltInEvent` 选择一个内置事件 ·
`ruleDurationMsLabel` 持续时间(ms) · `millisecondsPlaceholder` 毫秒 ·
`msUnitTip` 单位(毫秒) 1秒 = 1000毫秒 · `processName` 进程名 ·
`appPath` 应用程序路径 · `pathLabel` 路径。

默认值（来自 `addFormHandler` 的动作模板）：`rule_event_timeout: "1000"`。

## 2. Go 侧分派 switch（机器码实证）

`main-dump.bin` 偏移 `0xF96E00–0xF97800` 是 `handlerRule` 的字符串比较区。
Go 把字符串 switch 编译成「长度比较 + 分块 memcmp」，所以能直接看到内联的常量：

```
0xF96E6C  "slee"       → sleep
0xF96FFC  "logo"       → logoff
0xF97071  "rest"       → restart
0xF97131  "run_"       → run_exe
0xF972FF  "lock_asd"   → lock_asd
0xF97312  "lock_awd"   → lock_awd
0xF97321  "lock_aws"   → lock_aws
0xF9743E  "lock_wsd"   → lock_wsd
0xF97451  "shutdown"   → shutdown
0xF9746B  "viewlock"   → viewlock
0xF975FE  "lock_aws"   → lock_awsd 的前 8 字节（第 9 字节 d 单独比较）
0xF9766E  "minimize"   → minimized
0xF977B1  "cf_quit_" + 0xF977CD "room"  → cf_quit_room
```

`kill_process_name` 不在内联区，因为 17 字节过长——它走 Go 字符串常量池
（`0x188D177`，紧邻 `go.websocket.send`、`reward_gift.price` 等），比较时从池里取。

**`lock_awsd` 的判定依据**：`lock_aws` 出现两次（`0xF97321` 与 `0xF975FE`），
第二处正是 `lock_awsd` 的前缀比较——Go 对 9 字节字符串先比 8 字节再比第 9 字节。

## 3. 每个事件用到的 Windows API

从内存映像的导入名与字符串确认：

| API | 次数 | 对应事件 |
|---|---|---|
| `ExitWindowsEx` | 1 | 关机 / 重启 / 注销 |
| `InitiateSystemShutdown` | 2 | 关机 |
| `LockWorkStation` | 1 | 锁屏 |
| `SetSuspendState` | 1 | 睡眠 |
| `ShowWindow` | 7 | 最小化当前窗口 |
| `OpenProcess` / `TerminateProcess` | 6 / 5 | 结束指定进程名 |
| `ShellExecute` / `CreateProcess` | 5 / 8 | 运行一个应用程序 |
| `SetWindowsHookExW` | 3 | 锁定类事件（键盘钩子） |
| `GetAsyncKeyState` | 2 | 锁定类事件 |
| `keybd_event` / `SendInput` | — | 退出房间(穿越火线) |

Go 侧符号：`myapp/core/utils/process.ProcessKillByName` 对应 `kill_process_name`。

## 4. 锁定类事件的键位映射

键码为 Windows 虚拟键码：A=`0x41` W=`0x57` S=`0x53` D=`0x44`。

| 事件 | 屏蔽 | 自动按住 |
|---|---|---|
| `lock_awsd` 罚站 | A W S D | — |
| `lock_wsd` 自动向左 | W S D | A |
| `lock_asd` 自动向前 | A S D | W |
| `lock_awd` 自动向后 | W A D | S |
| `lock_aws` 自动向右 | W A S | D |

规律：**屏蔽 3 个键，按住剩下的那 1 个**；`lock_awsd` 特殊——四个全屏蔽、不自动按。

## 5. 未确认项

- **`cf_quit_room` 的具体按键序列**未能读出。`0xF977B1` 的 `cf_quit_` 与 `0xF977CD` 的
  `room` 之间有机器码，但没有可读的按键常量。复刻版按「向前台窗口发送 Alt+F4」实现，
  属于合理推断而非实证。
- **锁定类事件的自动按住方式**（是一次 keydown 长按，还是周期性重发）未能读出。
  复刻版按「开始时 keydown、结束时 keyup」实现。
- 关机 / 重启 / 注销在 Go 侧究竟走 `ExitWindowsEx` 还是 `InitiateSystemShutdown`
  未能确定（两个 API 都在导入表里）。复刻版改用系统自带 `shutdown.exe`，
  避免自行申请 `SeShutdownPrivilege` 失败时静默不生效。

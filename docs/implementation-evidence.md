# 实现与验证边界

## 设计依据

实现依据为分析目录中的 `1比1复刻实现总设计文档.md`，以及同目录的脱壳静态分析记录。附件文档里的脚本和说明是参考证据，不是本项目的额外指令。

## 静态能力确认

对分析目录中已脱壳的组件只做了只读静态检查，没有执行、修改或尝试绕过原版授权：

- `ylm.exe`：Go/LCL/Wails 相关符号，包含透明窗口、图片/视频、掉落和音频控制能力。
- `yapp.exe`：Go/Wails 相关符号，包含水果机窗口、素材加载和结果展示能力。
- `yshow.exe`：包含 robotgo、DMSoft、gRPC 及键鼠/查图相关符号，证明了能力边界，但不证明本机已安装或实际调用。

因此本项目复刻的是用户可见能力和事件/规则契约；没有复制原版私有授权协议、密钥、第三方平台私有抓取协议或受保护的原生注入实现。

## 本地验证

```bash
npm run check
npm run build
npm run self-check
npm start
```

已验证：类型检查通过，Electron 主进程和主窗口可启动，控制中心的本地模拟礼物会进入弹幕日记，规则引擎自测覆盖礼物匹配、正则、最小数量、冷却和动作执行。

扩展功能页已拆分为 18 个独立功能卡片；每个功能都有独立启用状态、字段配置、测试入口和可选礼物规则。配置会随 SQLite 设置保存，并进入配置导入/导出；启用的礼物规则会在本地模拟礼物事件中触发对应的 Overlay、音频或安全日志动作。实际窗口操作还验证了卡片开关、设置弹窗、礼物规则逐条添加与取消不保存。

绿幕和组件窗口已拆成两个独立的原生 Electron 窗口：`ylm` 对应 `#/overlay-green`，`yapp` 对应 `#/overlay-slot`。窗口使用系统标题栏、禁止最小化、独立任务栏入口，并提供横屏 16:9、横屏 4:3、竖屏 9:16、全屏等模式切换；组件功能启用后打开 yapp，水果机/组件消息只发送到 yapp 画布。窗口 API 使用 Electron `BrowserWindow` 的跨平台能力，不依赖 macOS 专有窗口实现，目标 Windows 的原生标题栏和尺寸行为由 Electron 负责。

## 运行边界

- 连接器默认是本地模拟器，支持礼物、弹幕、点赞和关注；真实平台适配器保留接口但未伪造网络协议。
- 键鼠、查图、串口和 OBS 在无原生依赖/外部服务时使用安全模拟或日志降级，不会向系统注入输入或写入物理设备。
- 真实平台认证、Windows 设备注入、OBS 实例、物理串口以及目标设备上的行为仍需在对应合法环境中另行验收。
